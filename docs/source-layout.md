# Source layout

What each source file holds, and why the large ones stay whole. Splits follow cpp-libraries'
[`docs/SPLITTING.md`](https://github.com/Kronuz/cpp-libraries/blob/main/docs/SPLITTING.md).

## Library

- `strict_stox.hh` (1,510 lines): the whole library. It stays one file.
  - The contract is a single header: the README promises "One header, no dependencies" and tells
    users without CMake to copy `strict_stox.hh` onto their include path. SPLITTING.md keeps a
    library whose contract is a single file single-file unless the owner decides otherwise.
  - It is also one unit. `strict_stox_detail` holds the integer fast path, the Eisel-Lemire
    decimal path with its 5^q table (generated by `tools/gen_pow5.py`), the exact big-integer
    comparison, and the decline rules that hand a text to libc; the public `Stox` wrapper and the
    `strict_sto*` functions sit on top. Each layer exists to agree bit for bit with the next one
    down, and they share configuration macros (`STRICT_STOX_SWAR`, `STRICT_STOX_COUNT_LIBC`,
    `STRICT_STOX_STRTOD`, `STRICT_STOX_NOINLINE`) that the header defines and `#undef`s at its end.

## Tests and tools

No other file is over 1,000 lines: the largest are `tools/verify.cc` (995), `test/slow_test.cc`
(862) and `test/fp_test.cc` (754). `test/strict_stox_old.hh` is the frozen previous header kept for
the differential test and is never edited by hand.

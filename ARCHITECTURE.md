# Architecture

The internal design of `strict-stox`: a single header holding strict numeric
parsing over the C `strto*` family. For usage see `README.md`; for the repo map
and invariants see `AGENTS.md`.

## Shape

One header, header-only, zero dependencies beyond the C++/C standard library:

```
  strict_stox.hh   strict strto* wrappers, one throwing + one nothrow entry per parser
```

## The `Stox` wrapper

`Stox<F>` holds a name and a `strto*` function pointer. Its `_stox` core copies
the whole input into a NUL-terminated buffer (128-byte stack buffer, heap for longer text), runs the `strto*`
function, then enforces *strict* semantics:

- With no `idx` out-param, the parse must consume the entire string;
  otherwise it's `EINVAL`.
- With an `idx`, it reports how many characters were consumed and allows a prefix
  parse.
- Integer variants additionally range-check the result against the target type's
  `numeric_limits` and report `ERANGE` on overflow. This is what lets
  `strict_stoi` (which parses with `strtol` and narrows to `int`) reject a value
  past `INT_MAX`.

`errno` is saved and restored around each parse: the wrapper swaps the caller's
`errno` out, runs the parse, and swaps it back, surfacing the parse's `errno`
through the return path rather than leaving it in the global.

Two public methods sit on top: `stox_nothrow` writes the parse's `errno` into an
`errno_save` out-param and returns `0` on failure; `stox_throw` turns `EINVAL`
into `std::invalid_argument` and `ERANGE` into `std::out_of_range`, with the
message built by plain string concatenation.

## The clean-input fast path

Before the `strto*` path runs, `stox_nothrow` and `stox_throw` try a direct parse
(`strict_stox_detail::fast_int`, `fast_fp`) that touches neither `errno` nor a
buffer. It only accepts what every `strto*` reads the same way, and declines
(falls back to the path above, which then decides everything) otherwise:

- integers (`stoi`, `stou`, `stol`, `stoul`, `stoll`, `stoull`, `stoz`): an optional
  `-` (signed types only), then digits of the requested base 2..36, the whole input,
  1..63 bytes, no overflow of the function's own type. Whitespace, `+`, `0x`/octal
  prefixes, base 0 and invalid bases, trailing text, an embedded NUL, `-` on an
  unsigned function (`strtoul("-1")` wraps) and every overflow take the `strto*`
  path. A value outside the narrower target type (`stoi` of 3000000000) also takes
  it, so `ERANGE` always comes from one place;
- `stof`/`stod`: `[-]digits[.digits][e[+-]digits]` of any length. The text is reduced to
  `w * 10^q` (`w` the first 19 significant digits) and converted by a table-driven
  Clinger / Eisel-Lemire algorithm (below). `inf`, `nan`, hex floats, whitespace, `+`,
  trailing text, results that are subnormal, zero from a non-zero mantissa or
  infinite (`strtod` sets `ERANGE`), rounding in doubt, a locale whose decimal point is
  not `.` and a non-default rounding mode take the `strto*` path. `stold` has no fast path;
- the fast path applies only when the function is exactly `std::strtol` etc.; a
  `Stox` built around a custom function keeps its own semantics.

`test/diff_test.cc` compares the fast path with the frozen previous header
(`test/strict_stox_old.hh`) on random and edge inputs: value (bitwise), `errno_save`,
`idx`, `errno` preservation and exception text.

## Floating point conversion

`fast_fp` reads the text once and reduces it to `w * 10^q`: `w` is the first 19
significant digits as an integer and `q` the decimal exponent (the written exponent
minus the fraction digits, plus any digits dropped past the 19th). Digit runs are read
eight bytes at a time: one load, a branch-free test of every byte, the length of the
run from the trailing zero count, and three multiplies for the value, so a number of
any length costs a few instructions per eight digits and no loop that mispredicts on
the digit count. Then, in order:

1. **Clinger** (`double` only). When `w <= 2^53` and `|q| <= 22`, both operands are
   exact in a double and one multiply or divide is correctly rounded. Cheapest for
   the short numbers people actually write. Compiled out when floating point is
   evaluated in extended precision.
2. **Table** (`el_convert`). `pow5_tab` holds the 64 leading bits of `5^q` for
   `q` in `[-326, 308]`, truncated (635 entries, 5 KB, generated by
   `tools/gen_pow5.py`, which also proves `floor(q log2 10) == (q * 217706) >> 16`
   over the range, the binary exponent formula the code uses). `w` is shifted left until
   its top bit is set, multiplied by the entry (one 64 x 64 to 128 bit multiply), and the
   leading 54 bits of the product (25 for `float`) are rounded to nearest. Since the
   entry is truncated, the exact product lies in `[P, P + 2^64)` where `P` is the
   128 bit product. The rounding is the same for every value in that interval unless a
   halfway point falls inside it. With `sh` the number of bits of the high word below the
   rounding bit (9 or 10 for `double`), that is exactly when the low `sh + 1` bits of the
   high word are `01...1` and the low word is not zero, or `10...0` and the low word is
   zero (an exact tie, or a product that is exactly a halfway point). Those cases, about one in 1000 for `double` and never in practice for
   `float`, are declined, so there is no second multiplication and no big integer
   fallback inside the fast path. A result that would be subnormal or infinite, or that
   rounds up into the normal range from below it, is declined too (`strtod` sets
   `ERANGE` there).
3. **More than 19 digits.** The first 19 significant digits give `w`; if any later
   digit is not zero the exact value is strictly between `w` and `w + 1` (in units
   of `10^q`). Rounding is monotonic, so when `w` and `w + 1` convert to the same
   value, so does the text. Otherwise the call is declined.

The conversions round to nearest. `strtod` follows the current rounding mode, so the
fast path is skipped when it is not to nearest (`rounds_to_nearest`, a volatile
`1 + tiny == 1 - tiny` test). It is also skipped when the locale's decimal point is not
`.` and the text has a `.`, because `strtod` would read `1.5` as `1` there. That test is
a libc call (`nl_langinfo`, `localeconv` without `langinfo.h`; 3 ns on Apple silicon,
5 ns on an Intel laptop) next to a parse of 6 to 20 ns, so a program that never leaves the
C locale can define `STRICT_STOX_C_LOCALE` before including the header to read `.` without
asking.

`test/fp_test.cc` states the property the path must keep: whenever `fast_fp` accepts
a text, `strtod` (`strtof`) returns the same bits with `errno` clear and consumes the
whole text. It also checks the table against exact big-integer arithmetic, the hard
cases, the exact halfway point of every binade, and random text in many formats
against libc and `std::from_chars`. `test/rounding_test.cc` runs the public API in each of
the four rounding modes against libc, and `test/locale_test.cc` tests the decimal point guard
with a mock decimal point (`STRICT_STOX_DECIMAL_POINT`, a seam for tests) and, where one is
installed, a real comma locale. `tools/fp_mutants.py` breaks the implementation in 37
deliberate ways and requires each to fail the tests; the rounding and locale mutants must
fail their own test.

## The `STOXIFY` macros

`STOXIFY` and `STOXIFY_BASE` stamp out the two free-function entry points for each
parser from one line. `STOXIFY_BASE` is for the integer forms that take a `base`
argument (`strict_stoul`, `strict_stoi`, ...); `STOXIFY` is for the
float/`base`-less forms (`strict_stof`, `strict_stod`, `strict_stold`). The `T`
template argument selects the type to narrow and range-check to, or `void` to keep
the `strto*` return type. So:

```cpp
STOXIFY_BASE(stoi, std::strtol, int)   // parse with strtol, range-check to int
STOXIFY(stod, std::strtod, void)       // parse with strtod, keep double
```

each expands to a throwing `strict_stoX(str, idx, base)` and a nothrow
`strict_stoX(errno_save, str, idx, base)`.

## Why this shape

`std::stoi` and friends are almost what you want but quietly accept trailing
garbage (`std::stoi("42abc")` returns `42`), which hides bugs in config and query
parsing. This header's contract is the strict one: with no `idx`, the whole string
must be a number. Building it as a thin layer over `strto*` keeps it tiny and
fast, and routing every parser through one `Stox` core means the strict check, the
range check, and the `errno` discipline are written once. The throwing/nothrow
split lets call sites that already sit inside a `try` use exceptions while hot,
allocation-sensitive paths use the `errno_save` form. Standard exceptions in
place of Xapiand's `THROW` macros let it stand alone with no project dependency.
